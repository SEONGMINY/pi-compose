## 지키는 제품 계약

- **Main Agent**는 프로젝트·기능·작업별로 여러 개. 요구사항·설계·의사결정의 원본 대화.
- **Work Agent**는 선택한 Main의 정확한 저장 JSONL을 Fork한 별도 세션. 작업 로그는 원본 Main에 자동 삽입하지 않는다.
- **Support Agent**는 탐색·조사·테스트·검증용 독립 Pi 세션. Main 아래에 나타나는 것은 관련 작업 표시일 뿐 대화 상속이 아니다.
- 화면에서 Agent를 닫는 것은 **Pi 실행 중단이 아니다**. 명시적으로 중단할 때만 프로세스를 종료한다.
- 세션 맥락은 Pi JSONL, 코드는 Git이 정본. 자동 요약·TODO·자동 병합·자율 계약 변경은 추가하지 않는다.
- 컨텍스트 패널은 **실제 기록**을 보여준다. 모델이 특정 결정을 중요하다고 이해했다고 추측하지 않는다.
- Git Shared/Worktree는 Fork/Independent와 독립적으로 선택한다.
- Auth credentials는 Pi의 기본 인증 저장소가 처리하고, Electron renderer로 전달하지 않는다.
- macOS Cmd+Q의 기존 실행 중단·세션 보존 정책 유지.

## 사용법

```bash
git fetch origin
git switch feat/ade-workspace-ux-and-terminal-fixes
npm install
npm run ade:dev
```

상단 프로젝트 메뉴에서 다른 Git 프로젝트를 추가·전환하고, 좌측 Main을 선택한 뒤 Work/Support를 여러 개 연다. 터미널 경계선을 잡아 크기를 변경한다. 각 터미널의 **맥락**에서 실제 Pi 원본 기록을 확인한다. 계정 연결은 우측 **계정 · 로그인**에서 진행한다.

빌드: `npm run ade:check && npm run ade:build`.

## 검증과 주의

이 PR 작성 환경은 macOS가 아니며 의존성 설치가 불가하다. 이번 변경은 **실행 테스트 통과를 보고하는 PR이 아니다**. GitHub Actions macOS 빌드 구성을 추가했다.

우선 확인할 회귀 시나리오:
1. Main A/B를 만들고 A에서 Work, Support 여러 개를 실행. 2분할·3분할·4분할, 크기 드래그, 탭 복귀 후 Ghostty 화면 확인.
2. 한글 IME 입력·조합 확정 및 Pi 입력창 중복 표시 확인.
3. 창 닫았다가 다시 열어 같은 PTY 화면이 다시 그려지는지 확인.
4. 프로젝트 2개 전환 후 기존 Worktree·모든 세션·열린 패널 보존 확인.
5. Main → Work Fork 세션 헤더 `parentSession`, Support 세션에 Main 대화가 복제되지 않았는지 비교.
6. 맥락 기록의 원문과 실제 Pi JSONL 대조, Agent 활동 표시는 Pi 이벤트에만 기반하는지 검증.
7. 앱 로그인 성공·재실행 후 인증 유지. GPT-5.6 Luna 신규 세션의 실제 모델 선택 확인.

맥락 요약이나 실행 상태를 추측해 UX를 개선하는 대신, 실제 근거가 있을 때만 추가 정보를 표시한다.
