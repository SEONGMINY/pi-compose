# 작업 중심 Hub · Ghostty 선택형 탭 (PR #3)

이 단계에서는 Main 작업 흐름에서 기술 식별자를 외우지 않고 작업을 찾는 데 집중합니다.

## 빠른 사용법

- 프로젝트에서 `pic`을 실행하면 입력창 아래에 **Alt+W 작업 보기** 안내가 표시됩니다.
- Main에서 자연어로 “기존 논의를 이어서 개발 에이전트에게 맡겨줘. 별도 Worktree를 사용해줘”라고 요청할 수 있습니다. 실제 실행은 사용자 확인 후 수행합니다.
- `Alt+W` 또는 `/compose`로 작업 Hub를 엽니다. **새 에이전트에게 맡기기**도 Hub에서 선택할 수 있습니다. 현재 프로젝트에서 승인 후 실행된 작업을 작업명으로 보여줍니다.
- 개발 작업을 선택하면 정확한 tmux 세션 또는 Worktree 실행 대상으로 이동합니다. 현재 위치가 Main이 아니고 원래 Main 실행 세션이 확인되면 **← Main으로 돌아가기**가 첫 항목에 표시됩니다.
- 작업 Hub의 **다른 저장 대화 / 이전 작업 찾기 (고급)**에서는 과거 Pi 대화·Worktree를 기존 메뉴로 탐색할 수 있습니다. 기존 `/compose back`은 호환성을 위해 유지합니다.
- `/compose launch`와 `/compose preview`는 숙련 사용자용 명령으로 유지합니다.

Hub는 현재 실행 중인 모델의 정확한 활동 여부나 개발 완료를 판단하지 않습니다. **실행 대상 열림 ≠ AI가 코드를 작성 중 ≠ 작업 완료**입니다.

## 작업을 어떻게 묶나요?

Pi Compose의 **새로 실행된 작업**에 대해서만 작업 제목·Context·Workspace·정확한 실행 식별자·원래 Main tmux 세션을 기록합니다.

- 위치: `~/.pi/compose/tasks/<프로젝트 해시>/<작업 ID>.json`
- 코드·대화 전문·모델 출력·프롬프트 파일은 이곳에 복제하지 않습니다.
- tmux와 workmux를 조회해 작업 기록이 가리키는 대상이 여전히 열려 있는지만 검사합니다.
- 같은 브랜치 이름이 다른 프로젝트에도 있으면 프로젝트 경로를 비교합니다. Worktree와의 연결이 모호하면 하나를 임의 선택하지 않습니다.
- **이전 버전에서 만든 작업**은 근거 없는 이름 유추로 합치지 않고 고급 탐색 화면에 둡니다.
- 작업 기록은 자원 자체가 아닙니다. Hub를 종료하거나 기록을 잃어도 기존 tmux·Worktree·Pi 대화는 유지됩니다.
- 파일은 별도 UUID 이름으로 생성되므로 동시 실행 시 하나의 공통 JSON을 서로 덮어쓰지 않습니다. 이 버전은 기록 삭제·정리 기능을 자동 실행하지 않습니다.

## Ghostty (macOS, 선택형)

Ghostty **1.3 이상**에서 AppleScript 권한을 허용한 뒤 일반 터미널에서:

```bash
export PIC_GHOSTTY_TABS=1
pic
```

이 설정을 사용하면 **Shared Directory 작업**을 Hub에서 선택했을 때 해당 tmux 세션에 연결된 Ghostty 탭을 새로 엽니다. **새 Worktree 실행은 `workmux add --mode session --background`를 이용**하므로 다른 tmux 세션으로 분리됩니다. Worktree가 실제로 열린 상태이고 해당 작업 디렉터리에 해당하는 단 하나의 tmux 세션을 확인할 수 있을 때만 Ghostty 탭에 연결합니다. 같은 작업 탭이 이미 존재하면 태그로 구분해 다시 선택합니다. 기존 Pi 프로세스를 복제하지 않습니다.

- Ghostty를 찾을 수 없거나 자동화 권한이 거부되면 일반 tmux 이동을 사용합니다.
- 기존 window 모드에서 생성된 Worktree나 정확한 세션을 찾지 못한 Worktree는 **기존 workmux 전환**을 사용합니다. 새 Pi 프로세스를 임의 실행하지 않습니다.
- Ghostty 모드에서 새 Worktree 실행 방식은 명시적으로 **session 모드**가 됩니다. 이는 사용자가 설정한 기존 workmux window 모드와 다를 수 있으므로, 동작을 확인하고 사용하세요.
- tmux·workmux 사용 환경이나 사용자 설정 파일은 바꾸지 않습니다.
- 다른 터미널에서는 `PIC_GHOSTTY_TABS`를 켜더라도 기본 Pi Hub와 tmux 탐색이 동작합니다.
- Mac 한국어 키보드/입력기에서 `Option+W`가 Pi의 Alt 단축키로 전달되지 않을 수 있습니다. 이 경우 `/compose`를 사용하세요. Ghostty `macos-option-as-alt` 설정을 확인할 수 있지만 Pi Compose는 해당 설정을 임의 수정하지 않습니다.
- macOS Ghostty에서 발생할 수 있는 권한 확인, 기존 탭 재사용, 탭 종료/재연결은 실제 사용자 환경에서 추가 검증해야 합니다. 이 단계에서는 정적 검사와 분리된 도구 검증만 수행합니다.

## 실사용 확인

1. `pic` 실행 직후 화면에서 `Alt+W`를 발견할 수 있는가?
2. Main에서 Worktree Agent를 생성하면 작업 이름이 Hub에 **한 번**만 나타나는가?
3. 실행 대상의 열림과 작업 완료를 혼동하지 않는가?
4. 선택한 작업으로 이동했다가 이전 Main 화면으로 돌아올 수 있는가? (Worktree의 Pi에 Compose Extension이 로드되어 있어야 동일 단축키 사용 가능)
5. Ghostty 모드에서 Shared Agent 탭이 중복 생성되지 않는가?
6. 기존 사용자 Worktree 설정, Pi 세션, 미커밋 파일이 유지되는가?

이 개선은 기능 구현과 화면 구조를 검증하기 위한 **초기 버전**입니다. macOS에서 두 개 이상의 인증된 모델로 실행하는 End-to-End 결과를 아직 확인하지 않았으므로 PR은 Draft로 유지합니다.
