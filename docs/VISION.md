# Vision — Pi Compose

> 상태: 프로젝트 비전 · 2026-11-10
>
> 현재는 제작자의 직접 사용 경험에서 출발한 단일 프로젝트입니다. 별도의 팀·개인 비전이나 검증되지 않은 시장 목표를 만들지 않습니다.

## 지향하는 미래

**개발자가 Coding Agent와 오랫동안 협업해도 설계와 결정의 맥락을 잃지 않고, 실제 개발을 분리해 수행하며, 다음 판단을 계속 내릴 수 있는 환경을 만든다.**

요구사항을 기억하는 것만으로는 충분하지 않습니다. 왜 그 결정을 했는지, 어떤 대안을 버렸는지, 무엇이 확정이고 무엇이 불확실한지가 이후 개발에서도 유지되어야 합니다.

## 누구를 위한가

Agent와 문제·도메인·API·제약을 깊이 논의하고, 그 논의를 유지하면서 구현과 검증 작업을 분리하고 싶은 개발자입니다. 현재 확인된 사용자는 프로젝트 제작자이며, 외부 사용자에게 같은 문제가 일반적이라고 주장하지 않습니다.

## 지속적으로 지킬 가치

- **맥락의 충실도:** 중요한 결정과 WHY, 제약의 강도, 승인 여부가 전달 과정에서 바뀌지 않습니다.
- **판단과 실행의 분리:** 일시적인 탐색·구현·테스트 기록 때문에 중요한 설계 대화를 잃지 않습니다.
- **사용자 통제:** Agent의 제안·보고·검증 결과를 승인된 사용자 결정으로 바꾸지 않습니다.
- **조합 가능한 환경:** 기존 Pi의 세션과 Extension을 존중하고 불필요한 별도 런타임이나 관리 계층을 강제하지 않습니다.

## 바라는 결과

다음 작업을 시작할 때 이전 결정을 반복 설명할 부담이 줄고, 별도 작업 결과의 근거와 불확실성을 이해할 수 있으며, Main에 무엇을 반영할지는 개발자가 결정합니다. 구체적인 지표는 실제 사용자 검증이 생기면 정합니다.

**문서 경계:** 사용자가 겪은 문제는 [Problem Statements](PROBLEM_STATEMENTS.md), 제품 요구사항은 [PRD](PRD.md), 기술 선택은 [Architecture](ARCHITECTURE.md)와 [TRD](TRD.md)를 참고합니다. Sidebar, Overlay, 명령어, 특정 Handoff UI는 비전 자체가 아닙니다.
