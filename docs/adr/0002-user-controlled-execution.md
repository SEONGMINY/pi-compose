# ADR 0002 — 실행과 세션 선택은 사용자가 통제

- 상태: **현재 적용** (2026-10-30 최신 결정 반영)
- 관련 제품 정책: [PRD](../PRD.md)

## 배경

Main은 사용자와 서비스의 목적·요구사항·제약을 논의하고, 어떤 작업에 맥락을 이어받은 Work가 필요한지 제안할 수 있습니다. 하지만 개발 Agent를 자동으로 생성하거나 일을 시작한다면 사용자가 실행 시점과 범위를 통제하기 어렵습니다.

이전 구현에서는 Pi/Git과 tmux·workmux를 조합하는 과정에 반복 조작 비용이 있었습니다. **도구 선택은 이후 Ghostty 단독 사용으로 변경했지만**, 사용자가 실행을 결정한다는 핵심 원칙은 유지합니다.

## 결정

1. **Main이 작업이나 실행 방식을 제안할 수는 있지만**, 사용자의 명시적 지시 또는 선택 전까지 Work/Support를 자동 생성·실행하지 않습니다.
2. Work는 사용자가 고른 Main의 **실제 Pi 활성 완료 세션**을 Fork하며, Support는 독립 컨텍스트에서 시작합니다.
3. Shared Directory/Git Worktree와 순차/병렬 실행 선택은 컨텍스트 상속 방식과 별개입니다.
4. 사용자는 이전 Main 대화를 **명시적으로 선택**해 다시 엽니다. Main을 선택하더라도 관련 Work/Support는 자동 재실행하지 않습니다.
5. **종료 요청 시 사용자에게 백그라운드 유지(최소화) 또는 실행 Agent 종료를 선택**하도록 합니다. 유지 선택은 작업이 계속 실행돼야 하고, 종료 선택은 프로세스만 종료하며 저장된 Pi 대화·Git 변경은 보존해야 합니다. Ghostty 기본 종료 확인창만으로 두 동작이 구현되는지는 검증이 필요합니다.
6. 사용자가 다른 Work에서 나온 중요한 결정을 Main에 **반영해 달라고 명시적으로 요청**하기 전까지 모델 컨텍스트에 자동 전달하지 않습니다.
7. Fork 전에 미반영 중요 결정 경고를 자동으로 띄우거나 다른 Agent의 결정을 자동 동기화하지 않습니다.
8. Git 병합·Worktree 삭제·대화와 문서의 롤백은 사용자 통제 아래 별개로 처리합니다.

## 이유와 한계

사용자 통제가 명확해지고 Main의 맥락이 개발 로그로 오염될 위험을 줄일 수 있습니다. 대신 사용자가 공유나 Git 통합을 놓칠 가능성이 있습니다. 이를 해결하기 위해 별도 상시 메시징/경고를 자동 도입하지 않고, 필수 Summary Overlay에 **공유할 중요 결정 후보를 자동 표시**하는 것까지 확정했습니다.

이 ADR은 세션 간 미전달 결정을 어떻게 자동 발견·전달하는지까지 정하지 않습니다. 다음 논의에서 결정합니다.
