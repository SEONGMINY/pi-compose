# ADR 0002 — 실행은 사용자 통제, 실행 옵션은 서로 독립

- 상태: **채택 — 제품 계약**
- 결정일: 2026-10-25 정리 (사전 설계 대화에서 합의)
- 연관 요구사항: [PRD](../PRD.md) FR-02~07, FR-12, FR-16

## 배경

자동 멀티 에이전트 오케스트레이터는 작업 분할·생성·스케줄링을 편리하게 할 수 있다. 하지만 사용자는 Main에서 요구사항을 정리한 뒤 **어떤 개발 세션을 언제 실행할지 직접 선택**하는 경험을 원한다.

또 개발 방식은 작업마다 다르다. 기능 간 의존성, 동시 수정 위험, 설계 맥락의 양은 프로젝트마다 달라지므로 Worktree, 독립 컨텍스트 또는 병렬 실행을 단일 정책으로 강제할 수 없다.

기존 도구를 수동 조합하는 방식도 문제였다. 사용자가 매번 Worktree 생성, cwd 이동, Pi Fork, tmux 연결, 결과 수집을 반복하면 비용이 사용자에게 전가된다.

## 결정

1. Main Agent는 작업·의존성·권장 실행 방법을 **제안**할 수 있지만 **사용자가 명시적으로 실행 요청·선택하기 전에는 개발 세션을 자동 생성하지 않는다.**
2. 세 차원은 서로 독립적인 선택이다.
   - Context: **Fork(원본 Session 지정) / Independent**
   - Workspace: **Shared Directory / Git Worktree**
   - Scheduling: **작업에 따른 순차·병렬, 사용자 실행 시점**
3. 사용자가 명시적으로 요청하면 Pi Compose는 기존 Pi·Git·tmux 기능을 조합해 반복적인 실행 준비를 자동 처리한다. 자연어 명시 요청도 사용자 실행 의도로 인정하지만, Main의 자율적 작업 위임과 구분한다.
4. 원하는 대시보드 경험은 세션 관찰·분할·전환·직접 제어다. 대시보드에 자동 스케줄러를 필수로 넣지 않는다.
5. 작업 완료 검증과 **Git 코드 통합 시점의 선택**은 별개다. 사용자가 실제 통합 시점을 통제한다.
6. Worktree 정리, 세션 종료, 브랜치 병합은 별도 행위다. 사용자 코드를 무단 삭제하지 않는다.

## 선택 매트릭스

| Context | Workspace | 허용 |
| --- | --- | --- |
| Fork | Shared Directory | ✅ |
| Fork | Git Worktree | ✅ |
| Independent | Shared Directory | ✅ |
| Independent | Git Worktree | ✅ |

병렬/순차는 네 조합 모두에 추가로 적용할 수 있다. Shared Directory 병렬 작업의 코드 덮어쓰기·귀속 불확실성은 알리되 금지하지 않는다.

## 비교했던 대안

| 대안 | 얻는 이점 | 포기한 이유 |
| --- | --- | --- |
| Main이 모든 개발 Agent를 자동 Spawn | 사용자 수동 실행 감소 | 원하지 않는 개발·관리 부담, 컨텍스트와 제어권 침해 |
| 모두 Worktree에서만 실행 | 파일 격리 쉬움 | 불필요한 브랜치·정리·통합 부담, 특정 업무에 맞지 않음 |
| 모두 Shared Directory에서 실행 | 준비 간단 | 병렬 수정 충돌과 변경 귀속 불확실성 |
| 항상 병렬화 | 벽시계 시간 단축 가능 | 의존 작업의 재작업 증가 |
| Pi/Git/tmux 명령을 매번 사용자가 직접 작성 | 초기 Harness 코드 최소 | 반복 조작·실수·작업 전환 비용 증가 |
| **직접 선택 + 기존 도구 실행 자동화** | 사용자 제어와 반복 비용 감소 | 최소 실행 연결 기능 및 안전한 오류 처리 필요 |

## 자율성 경계

- 사용자가 이미 선택한 실행 방식을 확인 없이 다른 방식으로 바꾸지 않는다.
- 기존 계약 안에서의 구현 세부 판단은 개발 Agent가 할 수 있다.
- 다른 에이전트에 영향을 주는 중요 변경은 직접 공유한다.
- 사용자 계약의 수정, 강한 금지의 완화는 실제 사용자 판단이 필요하다.
- 자동 인계 후의 **기본 기계적 검사**는 이미 사용자가 시작한 작업의 후속 처리로 허용되며, 자동 새 개발 에이전트 생성과 다르다.
- 명시적 실행의 단순 반복에 매번 새 승인 Gate를 요구하지 않는다.

## 적용 검증

- Main이 작업 계획을 작성해도 자동 Spawn 0건.
- 사용자가 Fork + Shared, Fork + Worktree, Independent + Shared, Independent + Worktree 각각 실행.
- 같은 명령 재시도/세션 재개 시 원래 세션을 잘못 대체하지 않음.
- 검증 통과 후에도 사용자가 통합을 선택하지 않으면 병합이나 Worktree 삭제가 발생하지 않음.

이 ADR은 **개발자의 의사결정**을 보호한다. 사용자가 셸 명령을 직접 여러 번 입력해야 한다는 뜻은 아니다.
