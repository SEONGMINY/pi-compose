# ADR 0003 — 기존 도구의 조합과 Main 컨텍스트 보호

- 상태: **핵심 원칙 유지 / 과거 tmux·workmux 실행 선택과 자동 검증 방안은 대체됨** (2026-10-30)
- 관련: [PRD](../PRD.md) · [TRD](../TRD.md)

## 배경

Pi Compose는 여러 에이전트를 하나의 새로운 런타임으로 재구현하는 제품이 아닙니다. Main의 깊은 맥락을 정확히 Fork하고, 독립적으로 처리할 작업과 긴 실행 기록을 분리하는 Harness입니다.

이전에는 tmux/workmux, Dashboard, 자동 Git 검사·독립 Reviewer 조합을 검토했습니다. 실제 유지보수·제품 이해 비용을 재평가하면서 **Pi + Ghostty 단독 실행**으로 방향을 변경했습니다.

## 현재 결정

1. **Pi**는 실제 세션/대화·Fork·Resume·Compaction·Extension/TUI를 담당합니다.
2. **Ghostty**는 터미널 표시·분할·포커스·실행 종료를 담당합니다. 구체적인 제어 API는 검증해야 합니다.
3. **Git**은 Shared Directory·Worktree·브랜치·Diff·코드와 문서 통합을 담당합니다.
4. **Pi Compose**는 정확한 Work Fork, 독립 Support 연결, 필요한 최소 실행 조합, Summary Overlay와 명시적 Handoff만 추가합니다. 새로운 런타임·작업 엔진·별도 GUI·범용 계약 DB를 만들지 않습니다.
5. Main에는 장기적인 의사결정·정책·이유를 남기고, 긴 구현·테스트·검증 출력은 Work/Support에 둡니다.
6. **Summary Overlay는 필수**이며 사용자에게 Work의 작업 보고와 중요한 결정 **공유 후보를 자동 표시**합니다. 표시 내용이 Main 모델 입력으로 자동 전달되는 것은 아닙니다.
7. Main Handoff는 **사용자 요청 때만** 수행합니다. 보고는 출처를 확인해야 할 주장이지, 자동 검증 완료나 Git 병합 승인이 아닙니다.
8. 승인된 중요한 프로젝트 결정은 기존 원본 문서에 즉시 갱신하는 방향입니다. 초기에는 짧은 지침+Pi 기본 파일 도구를 사용하고 실제 누락이 발생하면 보강을 검토합니다.

## 의도적으로 보류한 것

- Work A가 결정한 내용을 Main/Work B가 아직 모를 때 **어떻게 발견·전달할지**. Summary 자동 후보 표시만 확정했습니다.
- Support→Work와 Work→Work의 전달 UI/정확한 대상 및 수신 계약.
- Work의 문서 자동 수정 권한, 서로 다른 Worktree의 문서 최신성·동시 수정 처리.
- Summary 완료 상태, 상세 정보, 사용자 조작; Ghostty/Pi 실제 지원 범위.

## 제외

모든 Agent에 변경사항 방송, 모든 완료 턴의 자동 독립 Reviewer/테스트, 무단 Git 통합·세션 삭제, 자체 Dashboard/메시지 서버/계약 동기화 엔진은 현재 합의된 제품 범위가 아닙니다.

**이전 선택을 폐기한 이유:** 대규모 UI 통합과 복잡한 도구 조합이 Pi Compose 핵심 가치에 비해 제품 이해·유지보수 부담이 컸습니다. 기존 Pi·Ghostty의 실제 지원 기능을 먼저 사용합니다. 과거 구현/검증 기록은 Git 이력에서 확인할 수 있습니다.
