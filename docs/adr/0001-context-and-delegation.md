# ADR 0001 — 맥락 의존 개발은 Fork, 독립 작업은 별도 컨텍스트

- 상태: **채택 — 제품 판단 기준**
- 결정일: 2026-10-25 정리 (사전 설계 대화에서 합의)
- 연관 요구사항: [PRD](../PRD.md) FR-01, FR-02, FR-08, FR-09, FR-10

## 배경

사용자는 Main Agent와 장시간 요구사항·설계·예외·거절한 대안을 논의하면서 고품질 컨텍스트를 축적한다. 개발을 새 Sub-agent에게 짧게 넘기면 “왜 금지했는지”와 “절대” 같은 **제약의 이유·강도**가 누락될 수 있다.

반대로 파일 탐색, 웹 조사, 테스트 실행, 대규모 Git Diff 분석까지 모두 Main에서 수행하면 일시적인 결과가 활성 컨텍스트를 차지한다. 그 결과 중요한 설계 맥락을 유지하기 어려워지고 Compaction이 빨라질 수 있다.

## 결정

1. **Main 설계 컨텍스트에 깊이 의존하는 개발**은 지정 Main 세션의 Fork를 우선한다. 개발 Agent는 독립 세션에서 활동하며 Main의 컨텍스트를 불필요한 실행 로그로 오염시키지 않는다.
2. **독립적인 탐색·조사·테스트·검증**은 새 세션이나 Sub-agent를 우선한다. 필요한 정보와 결과만 Main에 전달한다.
3. 각 작업의 맥락 의존성과 독립성에 따라 선택한다. 모든 작업에서 Fork를 강제하지 않는다.
4. **Fork는 Worktree 선택과 별개**다. 어느 실행 경로도 특정 작업 공간을 자동으로 강제하지 않는다.
5. Compaction·Fork가 원본 대화의 모든 세부 의도를 활성 컨텍스트에 완벽히 보존한다고 주장하지 않는다. 중요한 결정의 원문은 Pi 세션 기록이나 기존 프로젝트 문서에서 확인할 수 있도록 한다.
6. Main에 전달되는 결과는 “무엇을 했는가, 왜 그렇게 했는가, 무엇이 불확실한가, 원문·코드는 어디에 있는가”를 중심으로 간결하게 한다.

## 비교했던 대안

| 대안 | 얻는 이점 | 포기한 이유 |
| --- | --- | --- |
| 모든 개발을 Main에서 수행 | 맥락 손실이 적음 | 테스트·탐색·Diff·코드 실행 정보로 Main 활성 컨텍스트가 소모됨 |
| 모든 작업을 새로운 Sub-agent로 시작 | 실행 간 격리와 낮은 초기 컨텍스트 | 이유·금지 강도를 짧은 위임 지시에서 잃을 수 있음 |
| 모든 세션을 항상 Fork | Main 맥락 전달 누락 감소 | 맥락이 필요 없는 작업도 많은 컨텍스트를 상속, 비용·오염 증가 |
| 기존 대화 전체를 매번 문서·DB에 재작성 | 세션 간 일관성 향상 가능 | 중복된 계약 관리와 문서 유지비용, 정본 혼동 |
| **작업 특성별 Fork/독립 선택** | 맥락 충실도·자원 소비 균형 | 선택 기준 및 원본 세션 식별 필요 |

## 영향과 트레이드오프

- Fork는 상세한 설계 이유를 가져갈 수 있지만 컨텍스트 크기와 비용이 늘 수 있다. 실제 프롬프트 캐시·모델 비용은 선택한 Pi/Provider 구성에서 검증해야 한다.
- 독립 세션은 초기 컨텍스트가 적지만 의미적으로 강한 계약을 판단하려면 기존 계약을 별도로 읽어야 할 수 있다.
- Main 컨텍스트를 보호하면서도 모든 판단을 자동으로 완벽히 재현하지는 못한다. 검증 시 원래 결정의 출처로 돌아가는 경로가 필요하다.
- “기존 코드가 그렇게 구현돼 있다”는 사실을 사용자 승인으로 해석하지 않는다.

## 적용 검증

- 사용자 지시 “이전 버전 호환성 때문에 API 구조 변경을 **절대 금지**”를 포함한 대화를 Fork한 뒤 이유·금지 강도가 유지되는지 확인.
- 독립 Test Agent가 방대한 로그를 처리해도 Main에는 결론·근거 위치만 남는지 확인.
- Fork + Shared, Fork + Worktree가 모두 가능해야 함.
